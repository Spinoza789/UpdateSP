Summary of changes made today
1. Group-buy add-on orders
Added support for placing an additional order against an already-paid group-buy order.
Add-ons are merged into the existing parent order rather than creating a separate active order.
The parent order keeps its:
Order code
Original payment status
Shipping address
Delivery method
Routing information
Group-buy metadata
The parent order totals and line items are increased by the add-on.
Only the incremental add-on amount is charged.
Existing parent balances are accumulated correctly when multiple add-ons are placed.
Add-on submissions preserve the original locked order address and do not add duplicate shipping charges.
Added validation and regression tests for parent-order eligibility and add-on total calculations.
Added redirect handling after a merged add-on order is submitted.
2. Payment and balance handling
Added explicit outstanding-balance handling for add-ons.
A paid group-buy order with a new unpaid add-on now shows:
Original payment confirmed
Original paid amount
Pending add-on payment outstanding
Add-on balance due
The fully-paid payment panel is hidden while an add-on balance remains unpaid.
Balance confirmation remains atomic and only clears the balance after successful confirmation.
Confirmed orders no longer rewrite their original payment amount when the payment page loads.
Removed the startup cleanup that was incorrectly clearing outstanding balances after a restart.
Added tests covering:
Paid parent plus unpaid add-on
Settled balance behavior
Protection against stale payment-lock rewrites
Startup protection against destructive balance resets
