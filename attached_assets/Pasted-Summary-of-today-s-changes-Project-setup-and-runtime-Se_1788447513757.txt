Inventory turnover logic
The original turnover logic tracked individual batch codes. That caused problems because Qiyunle usually assigns a new code when a product is replenished.

The logic now tracks turnover at the product level:

An OOS period starts only when total mapped stock for a product changes from positive to zero.
The OOS period closes when any new batch brings that product back above zero stock.
An older batch going out of stock no longer creates a false product-level OOS event while another batch remains available.
Duplicate open OOS events for the same product are prevented.
Existing false open events are not deleted; the admin report excludes open events for products that are currently in stock.
The average remains based only on completed turnover events.
The current database contains one completed historical event, so the existing average of approximately 0.22 days is not yet statistically representative. Future synchronisations will populate product-level events correctly.
